# ЛР6. Префиксы учебных счетов

Вариант: **Ledger**.

## Что дано

В записи уже есть `account_id`. Новое правило ещё не реализовано. Новая редакция также требует сочетать расширение с существующим поведением. Каркасы дополнительных типов даны; основной алгоритм сервиса уже готов.

## Задание

### Шаг 1. Завершите предметное расширение

Добавьте `AccountPrefixRule(prefixes)`. Оно разрешает `account_id`, начинающийся хотя бы с одного переданного префикса, иначе возвращает `ACCOUNT_PREFIX_DENIED`.

Сохраните собственный неизменяемый набор префиксов. Пустой набор запрещает все счета, пустой префикс в настройке вызывает `INVALID_CONFIG`. Подключите правило в сборке. Проверять существование счёта в другом сервисе не нужно.

### Шаг 2. Группа правил с тем же интерфейсом

Добавьте `PostingRuleGroup(rules)` как `PostingRule`. Сохраните `tuple(rules)`, не копируя объекты. Каждый элемент реализует `PostingRule`, иначе `INVALID_CONFIG`. Метод `check(entry)` вызывает правила по порядку, проверяет `CheckResult` (`INVALID_RESULT`) и возвращает первый отказ; последующие правила не вызываются. Пустая группа разрешает; исключения передаются наружу. Допустима группа внутри группы.

### Шаг 3. Подключите и сравните конфигурации

В сборке стандартные правила вместе с новым правилом объедините в `PostingRuleGroup`, а сервису передайте список из этой группы. Явно переданный набор не подменяйте. Проверки самого предметного объекта остаются обязательными. Изменение исходного списка не меняет группу; изменение самого правила видно, потому что объект не копируется.

### Шаг 4. Обязательная практическая часть

В `posting_rules.py` реализуйте `AmountBandRule(minimum, maximum)` через `PostingRule`. Два `Money` одной валюты задают включительный диапазон. При неверном порядке — `INVALID_CONFIG`; за пределами диапазона — `ENTRY_AMOUNT_OUTSIDE_BAND`. Хранилище и сервис не меняйте.

## Примеры и границы

- Префиксы `('ACC-', 'MERCH-')` разрешают `ACC-1` и `MERCH-1`, но не `EXT-1`.
- Пустой набор запрещает `ACC-1`; `('',)` вызывает ошибку настройки.
- Отказ не меняет журнал, прежние правила сохраняются.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.
