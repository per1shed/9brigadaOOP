# ЛР4. Один путь добавления записи

Вариант: **Ledger**.

## Что дано

Тесты проходят. Сервис сам вычисляет знак суммы, хотя `LedgerEntry.signed_amount()` уже готов; `record_debit()` повторяет проверки и запись из `record()`. Реализации `LedgerEntry.signed_amount` пока вынесены во временные процедурные функции `legacy_l4_*`. Они сохраняют поведение, но перенос в объекты ещё не завершён.

## Задание

### Шаг 1. Завершите перенос поведения в владельца

Перенесите тела `legacy_l4_*` в `LedgerEntry.signed_amount`, сохранив сигнатуры, свойства и проверки. Удалите временные функции: простой вызов старой процедуры из метода не завершает перенос.

### Шаг 2. Исправьте связанные вызовы сервиса

В `signed_total()` суммируйте значения `signed_amount()`. Метод `record_debit(entry_id, transaction_id, account_id, amount)` должен создавать запись `DEBIT` и передавать её в `record()`.

Сохраните проверку валюты. Методы хранилища и API не меняйте.

### Шаг 3. Сохраните всю последовательность

После E1 попытка E2 сверх лимита отклоняется. Следующая корректная E2 допускается: ошибочная попытка не заняла ID.

## Примеры и границы

- Итоги `DEBIT` и `CREDIT` не меняются; валюты не смешиваются.
- Повтор ID отклоняется и через `record()`, и через `record_debit()`.
- Отказ не добавляет запись.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).
